## 倒排索引构建过程

输入：词元文件 `tokens.tsv`，每条记录包含 `(doc_id, position, stem)`。

输出：按照词干组织的倒排索引，每个词干对应一个文档列表，每篇文档记录该词干出现的全部位置。

当前实现采用读入全部词元、排序、分组构建的方式，具体分为以下步骤：

1. 逐行解析词元文件，将记录保存到动态数组中。
2. 所有词元按照 `(doc_id, position)` 排序，统计涉及文档数，并检查是否有位置重叠的词元。
3. 所有词元按照 `(stem, doc_id, position)` 重排。
4. 顺序扫描重排后的词元：每遇到一个新词干，创建一个词项；在该词干内部，按文档编号分组，创建文档记录；将同一文档内的词位复制到位置数组中。

如果传入停用词清单，则在处理每个词干分组时，通过二分查找判断是否跳过整个分组。

伪代码参考如下：

```text
读取词元 T

按照 (doc_id, position) 排序 T
检查重复词位，收集文档编号

按照 (stem, doc_id, position) 排序 T
对每个词干分组：
    如果属于停用词，则跳过
    对组内每篇文档：
        保存该词干的有序位置数组

读取并校验可选文档清单
返回倒排索引
```

## 构建的复杂度分析

| 符号 | 含义 |
| --- | --- |
| $N$ | 输入词元记录数 |
| $V_0$ | 输入中不同词干的数量 |
| $S$ | 停用词条目数 |
| $D$ | 文档清单中的文档数 |
| $D_0$ | 词元中出现的不同文档数 |
| $P$ | 最终保留的位置总数，$P \leq N$ |

| 阶段 | 时间复杂度 |
| --- | --- |
| 读取词元、动态数组扩容 | $O(N)$ |
| 停用词排序 | 通常为 $O(S \log S)$ |
| 按文档和词位排序 | 通常为 $O(N \log N)$ |
| 检查重复词位、统计文档 | $O(N)$ |
| 按词干、文档和词位排序 | 通常为 $O(N \log N)$ |
| 分组构建倒排表 | $O(N)$ |
| 对不同词干检查停用词 | $O(V_0 \log(S+1))$ |
| 读取文档清单并验证编号 | $O(D+D_0 \log(D+1))$ |

排序采用快速排序。停用词排序为常数项，因此主要开销为词元排序，复杂度为 $O(N \log N)$。

空间复杂度分析：构建时同时保留输入词元和正在生成的索引，位置数组占用 $O(P)$ 空间。综合词项、停用词和文档信息，在字符串长度有界的假设下，空间复杂度为 $O(N+S+D)$。
